# 优先级分级表示例

> 参考：Tableau Pulse 功能优先级分级

---

## Tableau Pulse 功能优先级分级

### 一张表看懂：Pulse 的能力优先级

| # | 能力 | 优先级 | 理由 |
|---|------|:------:|------|
| 1 | **指标定义（Metric Definition）** | P0 | 整个产品的地基，没有它其他都不存在 |
| 2 | **自动洞察（Automated Insights）** | P0 | 核心差异化：系统主动发现变化，而非人找数据 |
| 3 | **自然语言摘要解释** | P0 | AI的核心价值：把统计事实变成人能看懂的话 |
| 4 | **趋势与异常识别** | P0 | 洞察的内容来源，没有检测就没有洞察 |
| 5 | **Driver/Contributor 原因分析** | P0 | 回答"为什么变了"，这是用户最关心的问题 |
| 6 | **Following（关注指标）** | P1 | 个性化基础，但属于使用机制而非AI能力 |
| 7 | **推荐问题（Guided Q&A）** | P1 | 降低分析门槛，但依赖前面P0能力先产出洞察 |
| 8 | **邮件/Slack 摘要推送** | P1 | 触达渠道重要，但属于分发机制 |
| 9 | **目标进度跟踪** | P1 | 绩效场景必需，但实现相对简单 |
| 10 | **Tableau Agent in Pulse（问答）** | P2 | 锦上添花，有更好没有也能跑 |
| 11 | **跨指标分析** | P2 | 进阶能力，单指标分析是前提 |
| 12 | **来源引用与支撑图表** | P1 | 信任基础，但没有它产品也能用（只是可信度低） |
| 13 | **洞察反馈排序（点赞/点踩）** | P2 | 长期优化用，早期没它不影响核心体验 |
| 14 | **多语言支持** | P2 | 国际化需求，非产品核心逻辑 |

---

## 分级说明

### P0 — 核心灵魂（缺一不可）

```
指标定义 → 统计检测(趋势/异常) → 贡献度分析 → 自然语言解释
```

这四项是**不可拆分的最小闭环**。缺任何一个：
- 没有指标定义 → AI 无对象可分析
- 没有统计检测 → 不知道发生了什么
- 没有原因分析 → 只能告诉用户"变了"但不知道"为什么"
- 没有自然语言解释 → 用户还是得自己看数字

### P1 — 有了 P0 后，让产品真正可用（体验层）

| 能力 | 为什么重要 |
|------|-----------|
| Following | 用户需要"我的指标"，否则千人一面 |
| 推荐问题 | 降低普通用户门槛，引导下一步 |
| 推送触达 | 不推送的话，用户还是会忘记看 |
| 目标跟踪 | 绩效管理场景必须有目标感 |
| 来源引用 | 企业场景需要信任感，否则不敢用 |

**判断标准**：去掉任何一个，产品能跑但体验会明显下降。

### P2 — 加分项，有了更好（进阶层）

| 能力 | 为什么是 P2 |
|------|------------|
| Agent 问答 | 核心流程已经能自动推洞察，问答是补充探索方式 |
| 跨指标分析 | 大部分用户先关注单指标，跨指标是进阶需求 |
| 反馈排序 | 需要积累足够用户数据后才有意义 |
| 多语言 | 产品逻辑无关，纯本地化工作 |

---

## 一句话总结

> **Pulse 的灵魂 = 治理好的指标 + 自动发现的洞察 + 说人话的AI解释**
> 
> 其他都是围绕这个核心做的体验增强和渠道延伸。

---

## 如何使用此模板

1. **列出所有功能/能力点**
2. **逐一评估**：如果去掉这个功能，产品还能跑吗？
   - 不能 → P0
   - 能但体验差 → P1
   - 能且影响不大 → P2
3. **检查依赖关系**：P0 是否真的是其他功能的前置？
4. **撰写理由**：每项用一句话说明为什么是这个级别
5. **输出表格**：按优先级排序，方便阅读
