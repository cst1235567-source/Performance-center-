# Performance Center 任务决策表

> 基于 Tableau Pulse 调研，提炼 PC 产品建设优先级  
> 更新日期：2026-07-31

---

## 一张表看懂：做什么 / 不做什么

| # | 能力/任务 | 建议 | 理由 | 优先级 |
|---|----------|------|------|:------:|
| 1 | **指标语义中心（KPI Wiki）** | ✅ **必须做** | 所有AI分析的基础，没有统一口径就没有可信AI | P0 |
| 2 | **AI回答展示证据（来源/图表）** | ✅ **必须做** | 用户能验证AI结论，否则无法用于经营决策 | P0 |
| 3 | **异常与变化洞察卡片** | ✅ **必须做** | 从"被动看报表"转向"主动发现"的核心能力 | P1 |
| 4 | **目标达成与进度跟踪** | ✅ **必须做** | 绩效管理的核心场景 | P1 |
| 5 | **订阅与消息推送** | ✅ **必须做** | 让洞察进入用户工作流，否则没人主动看 | P1 |
| 6 | **推荐分析问题** | ✅ **建议做** | 降低普通用户分析门槛 | P1 |
| 7 | **"我的指标"个性化入口** | ✅ **建议做** | 不同角色关注不同指标，首页应个性化 | P1 |
| 8 | **指标分析 Copilot（多轮问答）** | ⚠️ **可延后** | 有价值但依赖前面P0/P1能力就绪 | P2 |
| 9 | **洞察反馈排序（有用/无用）** | ⚠️ **可延后** | 优化体验用，非核心功能 | P2 |
| 10 | **行动任务闭环（待办→执行→跟踪）** | ⚠️ **可延后** | 差异化价值，但属于二期优化 | P2 |
| 11 | **直接让大模型连数据库自由分析** | ❌ **不要做** | 不可控、不可验证、不安全 | - |
| 12 | **一次性全量功能开发** | ❌ **不要做** | 应按 P0→P1→P2 分期迭代 | - |
| 13 | **脱离指标体系的通用ChatBI** | ❌ **不要做** | Pulse证明：受限领域Agent比通用助手更靠谱 | - |

## 核心原则（3条就够了）

### 原则1：先治理，再 AI
```
指标定义 → 统计计算 → 自然语言解释 → 用户决策
   ↑           ↑            ↑              ↑
 必须先有     AI不负责这步  AI在这里发挥作用  人来做
```
**没有指标语义层，AI就是空中楼阁。**

### 原则2：AI 的职责边界
| AI 该做的 | AI 不该做的 |
|-----------|-------------|
| 解释变化原因 | 决定指标口径 |
| 生成自然语言摘要 | 擅自修改权限 |
| 识别异常和趋势 | 替代业务决策 |
| 推荐后续问题 | 编造无数据支撑的结论 |

### 原则3：分期建设顺序
```
第一期（基础）：指标语义中心 + 证据展示 + 异常洞察卡片
第二期（体验）：目标跟踪 + 订阅推送 + 个性化入口 + 推荐问题
第三期（进阶）：Copilot问答 + 反馈排序 + 行动闭环
```

---

## 一句话总结

> **PC 不是做一个"更聪明的报表系统"，而是做一个"主动帮用户管绩效的智能助手"。**
> 
> 起点不是加一个 Chat 入口，而是建好**可信的指标体系**。
